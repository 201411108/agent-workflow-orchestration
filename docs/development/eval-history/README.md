# 동작 검증 실행 기록

`npm run eval`이 실행마다 JSON을 남긴다. 실제 모델을 호출하므로 CI에서 돌지 않으며,
릴리스 전과 라우팅을 바꾸는 작업(1.7) 전후에 수동으로 실행한다.

## 기록 읽는 법

- `passRate`: 케이스별 통과 회차 / 전체 회차
- `checkPassRate`: 개별 검사 단위 통과율
- `failures[].category`: 계약 결함 / 컨텍스트 부족 / 모델 변동 (VERIFICATION.md L3)

임계값은 VERIFICATION.md에 있다. **사후에 낮추지 않는다.**

## 하네스 성숙도 주의

1.6 구축 중의 초기 기록은 하네스 자체에 결함이 있어 거짓 실패를 담고 있다.
비교 기준으로 쓰지 않는다.

## R6 발견의 분류와 해결 (2026-09-21 ~ 09-23)

첫 베이스라인에서 `envelope.source_exists`가 실패했다. `--runs 5`로 분류한 결과
**2/5 통과**였고, 실패 형태가 매번 동일했다. 무작위 변동이 아니라 체계적 패턴이므로
**계약 결함**으로 분류했다. 추적 결과 원인이 셋이었다.

| # | 원인 | 분류 | 조치 |
|---|---|---|---|
| 1 | "X가 없다"는 사실의 출처를 적을 자리가 없어 `source`에 서술을 넣음 | 계약 공백 | `glob:<패턴>` 형태 추가 |
| 2 | `needs`의 채워진 형태가 계약에 없어 역할이 설명을 덧붙임 | 계약 공백 | 토큰 하나만 쓰도록 명시 |
| 3 | 아직 만들지 않은 파일을 출처로 인용 | 계약 공백 | 명시적으로 금지 |
| 4 | 쓰기 권한 없이 docs-only 역할을 실행 | **하네스 환경** | 실행기에 `--permission-mode acceptEdits` |
| 5 | 배포 파일의 `Source: skills/...`가 소비자에 없는 경로 | **렌더링 결함** | `Contract:` 표기로 변경 |

4번과 5번이 중요하다. **하네스가 자기 환경 제약과 제품 결함을 계약 위반으로
오판하고 있었다.** 특히 5번은 배포된 역할 파일이 소비자 프로젝트에 존재하지 않는
경로를 `Source:`라고 알려주고 있었고, 역할이 그것을 근거로 인용한 것이다.
하네스가 없었으면 발견하지 못했을 제품 결함이다.

진행: 2/5 → (계약 1~3 수정) 4/5 → (환경 4 수정) → (렌더링 5 수정) → **5/5**

임계값은 낮추지 않았다.
