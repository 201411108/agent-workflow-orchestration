# 동작 검증 실행 기록

`npm run eval`이 실행마다 JSON을 남긴다. 실제 모델을 호출하므로 CI에서 돌지 않으며,
릴리스 전과 라우팅을 바꾸는 작업(1.7) 전후에 수동으로 실행한다.

## 기록 읽는 법

- `passRate`: 케이스별 통과 회차 / 전체 회차
- `checkPassRate`: 개별 검사 단위 통과율
- `failures[].category`: 계약 결함 / 컨텍스트 부족 / 모델 변동 (VERIFICATION.md L3)

임계값은 VERIFICATION.md에 있다. **사후에 낮추지 않는다.**

## 하네스 성숙도 주의

1.6 구축 중의 초기 기록은 하네스 자체에 결함이 있어 거짓 실패를 담고 있다.
비교 기준으로 쓰지 않는다.

| 기록 | 상태 |
|---|---|
| `2026-09-21T06-11-48` | ❌ 관찰기가 `system/init`의 에이전트 목록을 호출로 오인 |
| `2026-09-21T06-19-39` | ❌ `steps`가 역할 호출이 아니라 도구 호출을 셈 (D6 의미 위반) |
| `2026-09-21T06-31-05` | ❌ 사용량 한도로 일부 케이스가 빈 응답 |
| `2026-09-21T07-17-42` | ❌ 파서가 따옴표 감싼 스칼라를 못 읽음 |
| `2026-09-21T07-20-21` | ✅ **첫 유효 베이스라인.** 40/41, 5/6 케이스 |

## 열려 있는 발견

- **R6 `envelope.source_exists`** — `role-planner`가 쓰려다 실패한 파일을
  `facts_confirmed`의 출처로 인용했다. 존재하지 않는 파일은 근거가 아니다.
  1회 실행으로는 계약 결함인지 모델 변동인지 구분할 수 없다.
  `--runs 5`로 통과율을 확인한 뒤 분류한다.
  **임계값을 낮춰 통과시키지 않는다.**
